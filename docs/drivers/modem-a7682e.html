drv_modem_a7682e

Cellular modem driver for the SIMCOM A7682E (4G LTE Cat-1). C driver wrapping the Espressif esp_modem component.

Overview Partial

HAL TypeNetwork (hal_net_driver_t, HAL_NET_CELLULAR)
ChipA7682E
InterfaceUART
DescriptionMobile data: powers the module, waits for a ready SIM and a registration, and opens a PPP session that the whole TCP/IP stack can use. Also AT commands and SMS. Registered with the net manager as the LTE transport; the kernel's network coordinator switches it on and off from Settings → Mobile data.

Implementation

Sourcecomponents/drv_modem_a7682e/ (C)
WrapsESP-IDF esp_modem managed component
TestsAnswer parsers: host tests (tests/test_parse.c). On a T-Deck Max with a SIM: power-on through the expander, SIM detection, registration, a PPP session switched on at boot and from Settings, HTTP over LTE with WiFi switched off, and AT+CPOF power-down. Throughput at 115200 and 921600 baud, 17-minute soaks of transfers and idle periods at 921600, and 26 starts from power-off, each connected on the first dial. APN parsing: host tests.

Configuration

A driver entry in the board profile, id com.thistle.drv.modem-a7682e, "hal": "network":

KeyMeaning
uart_num, tx, rx, baud_rateThe UART, from the SoC's side: tx drives the module's RXD. baud_rate is the rate the module powers up at, 115200 unless AT+IPREX changed it.
fast_baud_rateThe rate both ends switch to (AT+IPR) once the module answers, or absent to stay at baud_rate. The module goes back to its power-up rate when it powers down; one left running by a reset of the SoC is looked for at both. The T-Deck Max uses 921600: with no RTS/CTS wired, a rate the SoC cannot keep up with loses bytes.
pwrkeyPWRKEY on a SoC GPIO, if it is wired to one.
pwrkey_expander, pwrkey_expander_pinPWRKEY on an IO expander pin instead.
pwrkey_press_levelThe level that presses the key: 0 for a line wired straight to the module's active-low PWRKEY, 1 behind an inverting transistor (the T-Deck Max's Q5).
power_expander, power_expander_pinThe expander pin that switches the module's supply, driven high for on. The driver cuts it only after AT+CPOF.
dtr, rstDTR, held low so the module never sleeps; RESET, held de-asserted.

The user's settings live in system.json: thistle_os.cellular.enabled (default off) and thistle_os.cellular.apn (default empty, the APN the network assigns).

Known Issues

  • The data session is plain PPP, not CMUX, so a modem carrying data answers no commands. Signal and operator are those read before dialling, and sending an SMS interrupts the session briefly.
  • Incoming SMS are not received. With mobile data off the modem is powered down, and with it on the SMS poll waits for a session to end, which it does not. CMUX would fix this.
  • A SIM with a PIN is reported, not unlocked. Turn the PIN off in a phone.
  • The UART runs at 921600 baud on the T-Deck Max. Measured over LTE: about 50 KB/s each way (42–57 KB/s over 28 transfers), against 9.8 KB/s down and 10.7 KB/s up at 115200. A PPP trace over about 6 MB found no corrupted frame.
  • A module that kept its data session through a reset of the SoC (a crash, a restart, flashing) is shut down with AT+CPOF and started again, not taken over. Dialled again in place, it stopped answering for 10 to 30 s at a time, at 115200 as at 921600, and took up to two minutes to carry data. Restarted, it had LTE up 27 s after the coordinator started.
  • With no APN set, the driver writes back the APN the network gave the default bearer (context 1), as the module reports it, before dialling. Rewritten with an empty APN, the first session after each power-on was ended by the module or went silent, eight times in nine. AT+CGDCONT is saved, so from then on the module asks for that APN at attach, and an empty APN written while attached does not change what it reports. A SIM from another network may therefore need its APN set in Settings. That is untested.
  • Each power-on creates esp_modem's UART task (4 KB of internal RAM) again, and esp_modem aborts, rebooting the board, if it cannot (create uart event task failed). That happened once in 13 off/on cycles when a T-Deck Max had 14 KB of internal RAM left; it now has about 180 KB.
  • Attempts run on the network coordinator's thread, one at a time, so a WiFi network lost meanwhile is rejoined once the attempt ends, up to two minutes later. Switching mobile data off ends an attempt through the transport's cancel, as soon as the step under way finishes: powering the module up, or one AT exchange.

Routing between WiFi and mobile data is described in docs/adr/0003-wifi-first-routing-left-to-esp-netif.md.
