ThistleOS / LVGL Apps

Building apps for the LVGL window manager

On ESP32-S3 boards an LVGL window manager hosts all fourteen built-in apps, the launcher included. This page covers what an app must implement to run under it, when ThistleOS calls that code, and which interfaces it can use.

✎ Edit on GitHub
S3 firmware only
The LVGL managers and the C apps they host are compiled into the S3 image alone. main/CMakeLists.txt defines THISTLE_LEGACY_C_APPS for esp32s3. Every other target boots thistle-tk and loads signed .app.elf files. Both simulators build the LVGL apps as well.

Two kinds of app

An app reaches the LVGL window manager in one of two ways. Most of this page is about the first, because all fourteen apps on the device today are written that way.

Built-in LVGL appLoadable .app.elf
Source lives inapps/<name>/, compiled into the firmwareIts own CMake project, like standalone_apps/notes/
Draws withLVGL itself: lv_obj_t, styles, every widgetThe thistle_ui_* widget API, which the manager turns into LVGL objects
Registered byYour *_app_register(), called from lvgl_apps_register_builtin()The ELF loader at boot, from /spiffs/apps/ and /sdcard/apps/
Runs onThe LVGL task, with the LVGL lock heldIts own FreeRTOS task, 8 KB stack
PermissionsOne permissions_grant() line in main/main.cThe manifest's list, only if the Ed25519 signature verifies

Write a built-in app when you need real LVGL: lists, multi-line text areas, custom styles, keyboard focus, anything the widget API cannot express. Write a loadable app when one binary has to run on every board and under either window manager, and read the gaps listed for that path first.

How the LVGL manager gets chosen

"window_manager" in config/system.json names a manager by its own name. At boot, thistle_wm_select() in components/ui/src/wm_select.c resolves it:

  • "lvgl-epaper-wm" flushes into the panel's framebuffer and refreshes the glass only after the UI has been still for 300 ms.
  • "lvgl-lcd-wm" flushes straight to the panel and shows a splash screen.
  • "auto", empty, absent or unknown picks e-paper when the display driver has a refresh() hook, LCD otherwise.
  • "thistle-tk" skips the LVGL apps entirely.

The selector returns the manager and a hosts_lvgl_apps flag together, and main.c registers the LVGL apps only when that flag is set. Both LVGL variants share lvgl_wm.c and manager.c. They differ in their flush callback and in whether the refresh is deferred. Your app code is the same for both. In the simulator, --wm NAME overrides system.json for one run.

Where your app sits

The window manager splits the screen once, in ui_manager_init(). The top 24 px belong to the status bar. Everything below is one LVGL object, the app area, which every app shares. You build your UI as children of it, and you delete those children yourself. No one else will.

The app manager in components/kernel_rs/src/app_manager.rs owns the lifecycle. It holds at most 20 apps, keyed by ID. A second registration of an ID returns ESP_OK but keeps the first, which is why each window manager registers only its own App Store and Flashlight.

The LVGL render task wakes every 10 ms. It polls the input drivers, takes the LVGL mutex, runs lv_timer_handler(), and flushes whatever changed to the display driver. Loadable apps never see an lv_obj_t. They get 32-bit widget handles, and the kernel's widget dispatcher forwards each thistle_ui_* call to the active manager's vtable.

What a built-in app implements

Two structs from thistle/app_manager.h and one registration function. That is the whole contract.

typedef struct {
    const char *id;          // "com.thistle.notes": unique, and what the launcher launches
    const char *name;        // label under the launcher icon
    const char *version;     // semver
    bool allow_background;   // stored, but launch() never reads it
    uint32_t min_memory_kb;  // stored, not enforced
} app_manifest_t;

typedef struct {
    esp_err_t (*on_create)(void);
    void (*on_start)(void);
    void (*on_pause)(void);
    void (*on_resume)(void);
    void (*on_destroy)(void);
    const app_manifest_t *manifest;
} app_entry_t;

esp_err_t app_manager_register(const app_entry_t *app);

The kernel keeps the pointer you pass, so both structs must be static. Any callback may be NULL.

CallbackThe kernel calls it whenYour app should
on_createSomething launches the app while it is UnloadedBuild the UI under ui_manager_get_app_area(). Return ESP_OK. Any other value cancels the launch.
on_startStraight after a successful on_createSet the status bar title and show your root object.
on_pauseOnly for the launcher on switch-away, or on app_manager_suspend()Save, then hide your root.
on_resumeLaunch while Backgrounded or SuspendedShow your root and set the title again.
on_destroyAny other app is launched: Home, Esc, or a launcher tapSave, delete your root object, free memory, and set every static pointer back to NULL.
Your app is destroyed, not paused
When anything launches another app, launch() runs on_destroy on the foreground app unless that app is the launcher. Every launch of your app therefore starts from on_create, with nothing left from last time. Keep state you want back in a file, not in a static that still points at a deleted widget.

The lifecycle as the kernel runs it

  • A failed on_create puts your app back to Unloaded and marks the previous app Running again. It does not call that app's on_resume or on_create, so a launcher that hid itself in on_pause stays hidden. Fail before you build anything, and clean up what you built if you fail later.
  • app_manager_kill() and the low-memory LRU eviction (under 50 KB free) both run on_destroy and then empty the slot. The launcher still shows the icon, but launching it fails with ESP_ERR_NOT_FOUND until the next boot. Nothing outside the tests calls kill or suspend today.
  • app_manager_launch() holds the app manager's lock while it calls your callbacks. Call it from an LVGL event handler, never from inside a lifecycle callback.

A minimal app

Apps under apps/ follow one layout, and cmake/thistle_apps.cmake relies on it. Each app needs both <stem>_app.c and <stem>_ui.c, or the simulator builds fail.

apps/hello/ ├── CMakeLists.txt ├── manifest.json # id, name, version, permissions; the firmware build does not read it └── hello/ ├── hello_app.h ├── hello_app.c # lifecycle + registration └── hello_ui.c # LVGL widgets
# apps/hello/CMakeLists.txt
idf_component_register(
    SRCS "hello/hello_app.c" "hello/hello_ui.c"
    INCLUDE_DIRS "."
    REQUIRES kernel ui thistle_hal
)
/* apps/hello/hello/hello_app.h */
#pragma once
#include "esp_err.h"
#include "lvgl.h"

esp_err_t hello_app_register(void);
esp_err_t hello_ui_create(lv_obj_t *parent);
void hello_ui_destroy(void);
/* apps/hello/hello/hello_app.c */
#include "hello/hello_app.h"
#include "thistle/app_manager.h"
#include "ui/manager.h"
#include "ui/statusbar.h"

static esp_err_t hello_on_create(void)
{
    return hello_ui_create(ui_manager_get_app_area());
}

static void hello_on_start(void)   { statusbar_set_title("Hello"); }
static void hello_on_resume(void)  { statusbar_set_title("Hello"); }
static void hello_on_destroy(void) { hello_ui_destroy(); }

static const app_manifest_t hello_manifest = {
    .id               = "com.example.hello",
    .name             = "Hello",
    .version          = "0.1.0",
    .allow_background = false,
};

static app_entry_t hello_entry = {
    .manifest   = &hello_manifest,
    .on_create  = hello_on_create,
    .on_start   = hello_on_start,
    .on_resume  = hello_on_resume,
    .on_destroy = hello_on_destroy,
};

esp_err_t hello_app_register(void)
{
    return app_manager_register(&hello_entry);
}
/* apps/hello/hello/hello_ui.c */
#include "hello/hello_app.h"
#include "ui/theme.h"

static lv_obj_t *s_root;
static lv_obj_t *s_count;
static int s_taps;

static void tap_cb(lv_event_t *e)
{
    (void)e;
    lv_label_set_text_fmt(s_count, "Tapped %d times", ++s_taps);
}

esp_err_t hello_ui_create(lv_obj_t *parent)
{
    const theme_colors_t *c = theme_get_colors();
    s_taps = 0;

    /* One root that fills the app area; on_destroy deletes just this. */
    s_root = lv_obj_create(parent);
    lv_obj_set_size(s_root, LV_PCT(100), LV_PCT(100));
    lv_obj_set_style_bg_color(s_root, c->bg, 0);
    lv_obj_set_style_border_width(s_root, 0, 0);
    lv_obj_set_style_radius(s_root, 0, 0);
    lv_obj_set_flex_flow(s_root, LV_FLEX_FLOW_COLUMN);
    lv_obj_set_flex_align(s_root, LV_FLEX_ALIGN_CENTER,
                          LV_FLEX_ALIGN_CENTER, LV_FLEX_ALIGN_CENTER);

    s_count = lv_label_create(s_root);
    lv_label_set_text(s_count, "Tapped 0 times");
    lv_obj_set_style_text_color(s_count, c->text, 0);

    lv_obj_t *btn = lv_button_create(s_root);
    lv_obj_set_style_bg_color(btn, c->primary, 0);
    lv_obj_add_event_cb(btn, tap_cb, LV_EVENT_CLICKED, NULL);
    lv_label_set_text(lv_label_create(btn), "Tap me");

    /* Keyboard boards: only objects in the default group get keys. */
    lv_group_add_obj(lv_group_get_default(), btn);
    return ESP_OK;
}

void hello_ui_destroy(void)
{
    if (s_root) {
        lv_obj_delete(s_root);   /* children and group membership go with it */
        s_root  = NULL;
        s_count = NULL;
    }
}

Wiring it into the build

  1. Put the component in apps/hello/. The firmware finds it through EXTRA_COMPONENT_DIRS in the top-level CMakeLists.txt.
  2. Add "hello|HELLO|hello" to THISTLE_OPTIONAL_APPS in cmake/thistle_apps.cmake. The entry reads <dir>|<flag suffix>|<source stem>. Neither simulator has a component system, and this list is how they find your sources. Extra source files go in apps/hello/sources.cmake as THISTLE_HELLO_SRCS.
  3. Add hello to PRIV_REQUIRES in components/apps_builtin/CMakeLists.txt.
  4. In components/apps_builtin/lvgl_apps.c, add an #ifndef THISTLE_HAVE_HELLO default of 1, the #include "hello/hello_app.h", and REGISTER(hello_app_register);. Wrap the last in if (has_radio) or if (has_gps) if the app needs that hardware.
  5. Pass THISTLE_HAVE_HELLO=${THISTLE_HAVE_HELLO} next to the other flags in simulator/CMakeLists.txt and wasm/CMakeLists.txt.
  6. Grant permissions in the THISTLE_LEGACY_C_APPS block of main/main.c, for example permissions_grant("com.example.hello", PERM_STORAGE);. The flags are PERM_RADIO, PERM_GPS, PERM_STORAGE, PERM_NETWORK, PERM_AUDIO, PERM_SYSTEM and PERM_IPC.
  7. Optionally, give it an icon in app_icon_symbol() in components/apps_builtin/launcher/launcher_ui.c. It matches substrings of the ID and falls back to LV_SYMBOL_FILE.

Boot: how your app reaches the screen

#CallWhat happens
1thistle_wm_select()Reads window_manager, returns the manager and hosts_lvgl_apps.
2display_server_register_wm()Makes it the active manager and calls its init().
3ui_manager_init()Creates the LVGL display, touch and keypad input devices, the default group, the theme, the status bar and the app area.
4lvgl_apps_register_builtin()Calls every app's register function, yours included.
5app_manager_register()Your app gets a slot in the Unloaded state.
6elf_app_scan_and_register(), permissions_grant()Loadable apps join the list, and built-ins get their permissions.
7, 8app_manager_launch("com.thistle.launcher")The launcher's on_create and on_start build the home screen.
9ui_manager_start()Starts the LVGL task. Nothing draws before this, so registration code must not wait on the UI.
10 to 12launcher tap handlerCalls app_manager_launch(your_id). The launcher gets on_pause, and your app gets on_create then on_start.

Threads, input and the screen

Which thread runs your code

Lifecycle callbacks and LVGL event callbacks run on the LVGL task, nearly always with the LVGL mutex held. A launcher tap and a Home press both reach app_manager_launch() from inside lv_timer_handler(), so you can call lv_* functions directly. Two exceptions apply. The launcher's first launch at boot runs before the LVGL task exists. Esc calls app_manager_launch() from the input callback, before the task takes the mutex, so on_destroy after an Esc runs without the lock.

Any other task must take the lock around every LVGL call. The Terminal app's UART reader does exactly this:

ui_manager_lock();
lv_label_set_text(s_status, buf);
ui_manager_unlock();

Keep the critical section short, because the render loop waits on it. Use toast_post() to show a toast from any task. toast_show(), toast_info() and toast_warn() build LVGL objects and belong on the LVGL task. In LVGL 9.2, lv_async_call() creates an LVGL timer, so it needs the lock as well. messenger_ui.c calls it without the lock, so don't copy that pattern.

Keyboard and touch

  • Touch arrives as an LVGL pointer device, and the usual LV_EVENT_CLICKED and friends fire on the widget under the finger.
  • The hardware keyboard is a keypad device bound to lv_group_get_default(). Only objects in that group receive keys. Add your focusable widgets, focus one with lv_group_focus_obj(), and read lv_event_get_key(e) in an LV_EVENT_KEY handler.
  • The manager maps '\n' to LV_KEY_ENTER, '\b' to LV_KEY_BACKSPACE, 0x1B to LV_KEY_ESC and '\t' to LV_KEY_NEXT.
  • Home and Esc both bring the launcher forward, which destroys your app. Home never reaches LVGL, and Esc is acted on before LVGL delivers it. Neither key works as an in-app back button, so give screens deeper than one level an on-screen Back.

Screen size, theme and status bar

  • The app area is the display width by its height minus 24. That is 240 × 296 on the T-Deck Pro, 320 × 216 on the T-Deck, 240 × 111 on the Cardputer. Read it at runtime with lv_obj_update_layout(parent) and lv_obj_get_width(), as Notes does, instead of hard-coding it. test_app_matrix.py fails any app whose first screen runs past the left or right edge.
  • theme_get_colors() returns primary, secondary, bg, surface, text and text_secondary, plus radius and padding. Use these instead of literal colours, since users switch themes from Settings.
  • sdkconfig.defaults enables LVGL's Montserrat 14, 18 and 22. Any other font has to be compiled into your app.
  • Set your title with statusbar_set_title() in on_start and again in on_resume.

E-paper

  • The e-paper flush converts every pixel to black or white at half luminance, with no dithering. Mid greys land on one side or the other, so check theme colours on a real panel or in the simulator's e-paper profile.
  • The panel refreshes only after 300 ms without a flush. A timer that redraws more often than that keeps the panel from refreshing at all.
  • Whether a refresh is fast or full follows the user's policy: fast, full, or auto, which makes every sixth refresh full. Call ui_manager_force_refresh() after replacing the whole screen to make the next one full and clear the ghosting.

Loadable apps under the LVGL manager

A loadable app includes app_sdk/include/thistle_app.h, declares a thistle_app_t with the same five callbacks, and exports it with THISTLE_APP(my_app). The thistle_app() CMake function in app_sdk/CMakeLists.txt builds it into <name>.app.elf. A manifest.json beside the ELF gives the ID, entry, architecture and permissions, and tools/sign_elf.py writes the 64-byte .sig. standalone_apps/notes/ is a complete example.

At boot the loader reads the manifest and verifies the signature over the bytes it has already loaded. Then it links the ELF against an allowlist:

  • A signed app gets the documented thistle_* wrappers (APP_VISIBLE_SYMBOLS in syscall_table.rs) and the permissions its manifest asks for. No lv_* symbol is on that list.
  • An unsigned app is refused in release builds. Debug builds load it with IPC only, so the only syscalls that link are thistle_msg_send and thistle_msg_recv.

Under the LVGL manager, lvgl_wm.c implements the widget API:

Widget APILVGL result
thistle_ui_get_app_root()The shared app area
create_container / label / button / text_inputA borderless transparent lv_obj, an lv_label, an lv_button with a centred label, a one-line lv_textarea
set_size(w, h)-1 is 100%, -2 is size to content
set_font_size(n)Montserrat 22 from 22 up, 18 from 18 up, otherwise 14
THISTLE_EVENT_CLICK / VALUE_CHANGED / KEYLV_EVENT_CLICKED / VALUE_CHANGED / KEY
colours0xRRGGBB

The handle table has 255 entries shared by every loadable app, and a create call returns 0 once it is full. Each thistle_ui_on_event() allocates a small context that is never freed.

Gaps on this path (checked against the code, October 2026)
  • On the device, the app manager's on_create for an ELF is elf_app_start(), which runs the ELF's entry point in a new task through esp_elf_request(). Nothing on the device reads _thistle_app_entry. Only the simulator's sim_app_loader.c does, and only there do your five callbacks run as written.
  • thistle_ui_* calls reach lvgl_wm.c without taking the LVGL lock, from the app's own task. Under the LVGL manager they race the render task.
  • The ELF's on_destroy is elf_app_unload(). It deletes the task and frees the ELF, but nothing deletes the widgets the app created in the shared app area.
Until these are closed, a built-in app is the dependable way to ship LVGL UI on S3.

Running it

The simulator links the real kernel and the same app sources:

cd simulator/build && cmake .. && make -j8

# e-paper and LCD managers, straight into your app
./thistle_sim --device tdeck-pro --wm lvgl-epaper-wm --launch-app com.example.hello
./thistle_sim --device tdeck     --wm lvgl-lcd-wm    --launch-app com.example.hello

# headless: exit after 3 s, list anything drawn off-screen, save the framebuffer
./thistle_sim --device tdeck-pro --headless --timeout 3000 \
    --launch-app com.example.hello --report-offscreen --screenshot hello.ppm

simulator/tests/test_app_matrix.py opens every built-in app on every device profile. It builds IDs as com.thistle.<name>, so add your app to UNGATED_APPS (or the radio or GPS tuple) if it uses that prefix. Run it from simulator/ with python3 tests/test_app_matrix.py.

On hardware, check the serial port first, since another reader on it breaks flashing:

idf.py build
tools/check_serial_port.sh /dev/ttyACM0
idf.py -p /dev/ttyACM0 flash monitor

Checklist

  • Static app_manifest_t and app_entry_t, with a unique ID.
  • on_create builds one root under ui_manager_get_app_area() and returns ESP_OK.
  • on_destroy saves state, deletes that root, and sets static pointers to NULL.
  • Status bar title set in on_start and on_resume.
  • Sizes read from the app area, colours from theme_get_colors().
  • Focusable widgets added to the default group, and an on-screen Back for nested screens.
  • Every LVGL call from another task wrapped in ui_manager_lock().
  • The app registered in thistle_apps.cmake, apps_builtin, lvgl_apps.c, both simulator CMake files, and main.c for permissions.
  • Opened in the simulator under lvgl-epaper-wm and lvgl-lcd-wm.
