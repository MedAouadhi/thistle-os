Release Flashing

How to install a tagged ThistleOS release from GitHub assets, verify checksums, and choose the correct image for firmware versus recovery.

GitHub Releases

Release assets

A release should include these downloadable assets:

  • thistle_os-<version>.bin — main ThistleOS firmware, for a kernel slot (kernel_a or kernel_b).
  • thistle_os-<version>.bin.sig — Ed25519 signature for the firmware.
  • thistle_os-<version>.bin.pub — public key used to verify the signature.
  • thistle-recovery-<version> — recovery firmware for the reserved recovery slot.
  • SHA256SUMS — checksums for every release asset.

Verify downloads

sha256sum -c SHA256SUMS

On macOS, install GNU coreutils or compare individual files with shasum -a 256 <file>.

Initial flash

For development boards, the normal first install is still an ESP-IDF flash from source because it writes the bootloader, partition table, the first kernel slot (kernel_a) and the initial otadata together. A board on the older table (with factory) moves to the two kernel slots with this one flash; NVS and SPIFFS are where they were and survive it:

. "$IDF_PATH/export.sh"
idf.py set-target esp32s3
idf.py build
idf.py flash monitor

Updating main firmware

The running kernel installs an update into its other kernel slot: copy thistle_os.bin and its .sig to /sdcard/update/ and install it from Settings. A new kernel that has not run for a minute is rolled back at the next reset.

For manual serial flashing, use idf.py flash, which writes kernel_a (at 0x20000) and resets otadata so that slot boots. Writing a .bin alone with esptool leaves otadata choosing whichever slot it chose before.

idf.py -p /dev/ttyACM0 flash

Updating recovery

Recovery's slot is reserved and not yet used: nothing boots it. In the current 16 MB layout, recovery starts at 0x920000 and has 0x280000 bytes available.

esptool.py --chip esp32s3 write_flash 0x920000 thistle-recovery-<version>
Do not cross-flash slots
The main firmware and recovery firmware are different binaries. Flashing either one into the wrong app slot can leave the board unable to boot without a serial reflash.
