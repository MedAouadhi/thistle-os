ThistleOS / Release Flashing

Release Flashing

How a ThistleOS release is made by pushing a tag, what it publishes, and how a device installs it: over the air, from the card, or by USB.

GitHub Releases

Releasing

A release is a tag pushed to the repository. GitHub Actions builds that commit on GitHub's hosted runners, in ESP-IDF's container, with no .env: a released firmware compiles in no Cohere or PodcastIndex key and no tailnet address, and Dictation, Podcasts, Hermes and AssistNow read theirs from the card.

  • v0.6.0 releases the firmware (.github/workflows/release-firmware.yml). The version the tagged commit describes must be the tag, and CHANGELOG.md must have a ## v0.6.0 - YYYY-MM-DD section: it becomes the release's notes and the text Settings shows. Without it the release stops before anything is published.
  • <app>-v1.0.1 releases one of the App Store's apps (notes, weather, wifiscanner, flashlight; .github/workflows/release-app.yml). The version must be the app's manifest.json version, its notes are metadata.json's newest release, and its min_os must be no newer than the newest firmware release.
  • A tag with a suffix, v0.6.0-rc.1, publishes a prerelease. The catalog leaves prereleases out, so no device is offered one; install it by USB or from the card to try it.

The release is signed with the publisher's one release key, which exists only as the secret RELEASE_SIGNING_KEY of the repository's release environment; that environment admits only tags matching v* and *-v*, and a tag ruleset limits who may push them. Its public half is tools/production_public.key, which every build of the kernel trusts. Releases are immutable and carry build provenance attestations; each one then redeploys Pages, which rebuilds the catalog.

Raising the security version

A release that fixes a security hole raises SECURITY_VERSION in components/kernel_rs/src/version.rs by hand before it is tagged. The release writes it into the signed artifact manifest. A device that keeps that kernel raises its security floor to it, and from then on installs nothing below it, from the network or the card, and offers no going back below it.

Release assets

A firmware release for the ESP32-S3 holds:

  • thistle_os-esp32s3-<tag>.bin — the kernel image, written into a kernel slot.
  • thistle_os-esp32s3-<tag>.bin.manifest and .bin.manifest.sig — the artifact manifest (version, security version, chip, boards, size, SHA-256) and its Ed25519 signature by the release key.
  • thistle_os-esp32s3-<tag>-full.bin — the full flash image: bootloader, partition table, the initial boot choice and the kernel, for setting up a device by USB.
  • thistle_os-esp32s3-<tag>.catalog-entry.json — the release's entry in the catalog.
  • SHA256SUMS — checksums of every asset.
sha256sum -c SHA256SUMS
gh attestation verify thistle_os-esp32s3-v0.6.0.bin --repo MedAouadhi/thistle-os
python3 tools/sign.py verify thistle_os-esp32s3-v0.6.0.bin.manifest --pubkey tools/production_public.key

Updating over the air

Devices read the catalog at https://medaouadhi.github.io/thistle-os/store/catalog.json once a day; a card's config/appstore.json can name another. Settings → System update shows a newer release and its notes, downloads it over WiFi (mobile data only when allowed), checks it against its signed manifest, writes it into the other kernel slot and asks Restart now or Later. A new kernel that has not run for a minute is rolled back at the next reset; once kept, Settings offers to go back to the previous version, still in the other slot.

Installing from the card

Copy the release's .bin, .bin.manifest and .bin.manifest.sig to /sdcard/update/ and choose Install from card in Settings → System update. It goes through the same checks, with no network; any version at or above the security floor installs.

Flashing by USB

A new device

Write the full flash image at 0x0. It fills the gaps between its parts, so it also erases NVS (settings kept there, the tailnet's sign-in, the security floor); SPIFFS and the card are beyond it and kept.

esptool.py --chip esp32s3 -p /dev/ttyACM0 write_flash 0x0 thistle_os-esp32s3-v0.6.0-full.bin

Moving a device over

A device on the older partition table (with factory), or one trusting upstream's key and catalog, moves to the two kernel slots, the release key and this repository's catalog with one USB flash of a build from source. NVS, SPIFFS and the core dump are where they were, so WiFi, settings and the mesh identity survive it. From then on it updates over the air.

. "$IDF_PATH/export.sh"
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor

idf.py flash writes kernel_a (at 0x20000) and resets the boot choice, so a USB flash always boots kernel_a. Writing a kernel image alone with esptool leaves the boot choice as it was. A build from source reports the version it was built from, such as 0.6.0-3-gabc123-dirty, and is offered only releases newer than 0.6.0.

Recovery

Recovery's slot (recovery, at 0x920000, 0x280000 bytes) is reserved: nothing writes or boots it, and no release includes it.
